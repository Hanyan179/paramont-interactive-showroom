# 展厅公共数据入口

四个展厅任务共用同一套公司与业务事实，前端布局、场景、动画和设计素材各自独立。

- `catalog.json` 指向 `../展示应用/public/data/catalog.json`，原始工作簿的唯一提取档案。67 条品牌档案不是自有品牌数量。
- `official-content.json` 指向 `../官网采集/showroom-content.json`，保留公司事实及来源。
- `brand/` 指向 `../展示应用/public/media/brand/`，使用官方标志。
- `domains.json` 是用户确认的展示领域及原表大类编号，不建立品牌归属或品牌—品类关系。
- `concepts.json` 是本次新增的原创三维概念记录，所有前端均可读取。每条保留概念身份及原表品类依据；不得用作真实型号、真实材质或制造承诺。

现有档案保持原位，通过符号链接提供统一入口，避免建立四份独立业务数据。不要把旧官网图片纳入新设计。

新应用在开发时直接读取这里，在离线构建时携带同一来源的快照并生成校验记录。更新后重新构建即可更新离线包。

任务对应关系：原展示应用；lusion-mountain/subchi-paramont；品牌融合世界（本任务，端口 5208）；品牌世界新方案/应用（三维建筑方案，端口 5217，由另一任务管理）。应用接入状态应以实际读取链路为准，目录存在不等于四套前端已全部接入。

2026-09-10 的接入核对：本版开发直接读取公共入口、构建打包公共入口快照；原展示应用持有公共入口指向的权威档案；三维建筑方案的 catalog.json 与权威档案当前字节一致，但仍是独立快照文件。其余方案的未来更新同步需要各自接入此入口，不应把当前内容一致称为持续同步已完成。本次不修改其他任务正在维护的前端。

### 客户与供应商的真实国家分布

`business-footprint.json` → `../展示应用/public/data/business-footprint.json`，是两份国家档案的唯一汇总入口。主展厅的“全球供应链”共用此数据，在同一入口内切换球形和平面视图。客户、供应商筛选与选中国家在两种视图之间保留，平面地图的缩放和位置也会保留；两种视图都进入原有的三地模型，并返回进入前的视图。其他前端可引用此数据入口；不代表其他前端已自动更新。

- 来源为用户提供的 `客户国家.xlsx`（Customer Master List，A2:E984）和 `供应商国家.xlsx`（导出结果，A2:E6422）。来源散列、原始国家代码计数与汇总口径保存在数据内。
- 客户 983 条，59 个国家和地区，36 条国家空缺；供应商 6,421 条，22 个国家和地区，98 条国家空缺。两表合计覆盖 65 个国家和地区。
- 按 C 列国家代码汇总，不从公司名称推断位置。英国 UK / GB 合并；PA 保留为巴拿马，原表翻译错误不视为国家缺失。未填写国家的记录计入总数但不落点。
- 数量指主档记录，不代表活跃客户、活跃供应商、自有工厂、交易额或实际物流。欧洲供应商记录不改变“公司欧洲无工厂”的已确认边界。三地模型入口继续使用原来的中国、柬埔寨、美国业务角色。
- 浏览器仅加载国家级汇总，不包含客户/供应商名称及编号。导入脚本只读原文件，不上传或修改原表。

后续收到新版原表，在主展厅目录运行：

```sh
python3 scripts/import-business-footprint.py /path/to/客户国家.xlsx /path/to/供应商国家.xlsx
```

脚本使用 Python 标准库，直接读取工作表中的行，避免供应商原表 `A1:A1` 尺寸声明导致漏读。遇到未知代码、重复或缺失档案编号会停止，不猜测映射。地理代码依据[联合国 M49](https://unstats.un.org/unsd/methodology/m49/overview/)，台湾地区沿用原表名称与本地地图 158 编号。展示只表达国家级覆盖，不能据此定位具体客户或工厂。
