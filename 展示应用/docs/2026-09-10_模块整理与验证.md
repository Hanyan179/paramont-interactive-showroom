# 模块整理与验证

## 结论

当前是一个企业展厅产品，包含主展厅与品牌产品模块两个前端运行部分；四区是业务导航，不是四套独立系统。九类开发职责及实际扩展路径见 [开发与扩展指南](开发与扩展指南.md)。

本轮保持已有界面、模型、材质、配色与业务浏览流程，整理共用基础能力。没有把既有产品重新制作成三套方案。

## 已落地的整理

| 修改 | 实际效果 |
|---|---|
| 四区配置 `src/config/areas.js` | 主导航、路由解析、总览标签/入口、产品区域归属使用同一份定义；旧品牌/品类深链接保留内部视图语义 |
| 加载文案 `uiCopy.js` + `SceneLoading.jsx` | 公司场景统一为“正在加载展厅”，产品模块为“正在加载品牌与产品”，替换“正在进入公司世界”等表达 |
| 巡展配置 `src/config/presentation.js` | 镜头清单与默认时间从计时引擎分离；新增已有场景镜头不需修改计时器 |
| 计时参数同步 | 后加载的 `settings.idleSeconds` 能更新正在使用的导演，且不重置当前巡展镜头 |
| 共用 `../共享组件/frameLoop.js` | 两边均在暂停/隐藏时取消帧调度；恢复第一帧时间增量为零，避免追赶长时间停留 |
| 主展厅 `scenePointer.js` | 统一点击/拖动阈值、主指针、取消、失去捕获、窗口失焦及释放；快速松手或拖回原点不会误选模型 |
| 文档 | 更新 README、集中当前 AGENTS 规则、添加扩展指南；旧项目规则原文归档，产品模块补充共享生命周期入口 |
| 检查入口 | 增加 `npm test` 与 `npm run check:content`，沿用现有构建和产品导出流程 |

未新增生产依赖。没有修改批准过的标志、样式及造型；主展厅样式构建仍为 `index-C8_mu_D2.css`，产品样式仍为 `index-yDrEwu-Z.css`。

## 本轮浏览器范围

使用现有 5183 服务和 1920×1080 固定画布检查页，检查主线衔接，未扩大产品内部业务测试。

- 中英文四区导航可切换；全局系统栏数量为 1，产品子模块无重复全局栏，未发现页面水平溢出。
- 公司章节切换和模型选择可用；实际拖动后检查角度由约 -0.12 改为 0.66，路由和选中公司未误跳转。
- 打开公司图文阅读时场景时间在两次观察中保持 109.30；关闭后继续更新，仍可选中公司。
- 公司动态进入经历 `approaching`、影片打开，再经历 `returning` 到 `closed`；影片仍可顺序循环，未变成直接弹窗替换。
- 工厂能力进入中国创研空间，切到数据分析后未残留工厂详情；数据阶段入口正常。
- 产品区显示正常，其活动期间父场景时间保持 256.37，产品帧数继续增加，表明两端的运行与暂停互不混淆。离开产品区后两次观察帧数均为 2577。
- 选择“儿童玩具”，切到数据分析再返回，仍保留“儿童玩具”领域，模块没有重新挂载。
- 手动启动统一巡展后，第一次触摸恢复公司章节，自动展示按钮回到未选中状态。90 秒自动启动与整套镜头循环由自动化检查覆盖，本轮未等待完整巡展时长。
- 固定尺寸检查容器观察到一次无源码定位的 `MutationObserver.observe` 参数错误。当前主应用、产品模块和检查页源码没有该调用；同类日志在既有检查记录中已有记载。本轮未声称修复该容器日志，也不把它记为新场景代码故障。

实际触摸屏、多指硬件、墙面观看距离和连续 30 分钟实机运行未在本轮执行。既有其他尺寸的记录保留，本轮浏览器检查不冒充重新完成所有尺寸验收。

## 仍需按功能逐步整理的部分

- `ConnectedScene.jsx` 仍是较大的场景协调器。几何工厂已经分开，但地球装配、各区域镜头/灯光混合与标签投影仍集中；新增复杂区域时应继续提取对应协调模块，不在这里无限叠加分支。
- `App.jsx` 仍集中较多跨区状态与恢复逻辑。下一次涉及新媒体或业务状态时，应按具体流程提取，不改成没有真实调用方的万能状态框架。
- 样式仍有历史分层覆盖，尚未成为全部由设计变量驱动的界面组件库。本轮不重排样式，避免改变已经认可的画面。
- 产品模块保留自己适合双指缩放、款式和目录的控制器；共享了帧生命周期，不声称两端所有交互代码已经合成一套。
- 当前地球可选三地。欧洲、澳洲的真实地点资料及新的独立模型接入属于后续业务工作，没有在架构整理中冒充完成。
- 新资料和现有镜头可以主要改配置；新模型仍需要造型、材质、机位、命中与内容接入以及实际视觉验收。
